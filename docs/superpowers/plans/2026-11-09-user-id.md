# Validación del formulario y escritura de User ID

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:executing-plans to implement this plan task-by-task.

**Goal:** comprobar la llegada al registro y escribir y verificar User ID.

**Architecture:** conservar los localizadores y las acciones en
`RegistrationPage`; usar las aserciones de AssertJ desde los pasos Cucumber.
Reutilizar `BasePage.type()` para esperar, limpiar y escribir.

**Tech Stack:** Java 21, Selenium, Cucumber, JUnit Platform y Gradle.

**Spec:** alcance propuesto en la conversación y aprobado por la usuaria:
validar el formulario y completar únicamente User ID. Consultar antes de
ampliar el alcance.

## Resultados y decisiones

La variable `CUCUMBER_FILTER_TAGS` no filtró esta suite con JUnit Platform;
la propiedad Java sí funcionó. Se corrigió el comando sin cambiar Gradle.
La prueba focalizada pasa; la suite completa tiene un escenario aprobado y
TC-SIGNUP-01 fallido por la firma sin `DataTable` del paso de formulario.
Se conservó ese fallo para evitar presentar como completo un flujo pendiente.
